# 个人求职 Agent 界面设计说明

日期为 2026-11-12。本文与[交互设计](DESIGN.md)、[技术设计](TECHNICAL_PLAN.md)组成完整重构方案，需求来源为 [REQUIREMENTS.md](REQUIREMENTS.md)。界面已按确认的 Demo 风格重写，当前验证范围见[重构实施状态](REBUILD_STATUS.md)。本文供界面实现使用，原设计方案已由本组文档替换。

## 1. 产品与页面任务

面向独立求职者的本地 Agent。用户用对话维护意向、发现机会、订阅变化、准备材料、辅助填写并跟踪申请。界面围绕当前目标、岗位、申请和下一动作组织。桌面端优先支持长时间阅读与比较，手机端保证查看结果、修改条件和接管确认可用。

主要入口为今日、助手、机会、申请、我的资料和设置。目标与订阅共用管理面板，材料和填写从岗位或申请进入。首次使用进入助手，已有记录时进入今日。

## 3. 页面构图

### 今日

首屏显示需要接管的任务和未确认的外部结果，随后显示到期行动、新机会、最近进展和来源问题。每项提供对象名称、原因、时间和直接动作。无数据时提供输入求职意向的入口。

### 助手

主区为连续工作记录，顶部可打开历史会话。右侧上下文区显示当前目标、已保存条件和运行状态，输入区上方固定显示操作对象。用户消息、保存回执、运行进度、岗位结果和接管面板使用不同结构。运行细节默认折叠，结果支持进入完整机会列表。

### 机会

顶部显示目标、条件和本轮覆盖。主体为可比较的岗位记录，包含公司、标题、地点、招聘类型、资格结论、理由、未知项和用户决定。目标和筛选在翻页后保持。每轮搜索的覆盖与错误可展开查看，历史岗位显示自身核验时间。

### 岗位详情

首屏同时显示岗位身份、资格结论、证据摘要和下一操作。主文档依次展开资格表、待确认项、推荐依据、项目与岗位要求、多来源和原始 JD。右侧操作区提供用户决定、材料、申请和相关历史，窄屏按阅读顺序排入正文。

### 目标与订阅

条件逐项区分硬条件和偏好。公司名单显示纳入理由、规模依据和检查结果。订阅显示时间、时区、范围、事件、资格未知策略、渠道、下一次执行和历史。暂停、恢复和立即检查的结果以实际配置更新呈现。

### 材料

并列呈现岗位要求、事实依据和建议差异。每条建议支持采纳、编辑和保留原文。最终预览显示固定版本及文件来源。事实缺失、基础简历更新和 JD 更新在相关建议位置提示。

### 填写

当前申请、页面和执行入口始终可见。预览显示拟填写、已有、缺失和需授权字段。执行结果可定位失败字段，接管面板提供原因、网页位置及继续入口。系统代提交确认单独呈现申请、页面、材料和动作，结果未知提供核对入口。

### 申请

台账显示公司、岗位、当前阶段、下一行动和日期。详情显示事件时间线、材料与填写历史。计划、完成、取消和修订状态明确区分。手工申请允许 JD 暂缺，新增重复或自定义阶段在当前申请内完成。

### 资料与设置

资料按个人事实、基础简历、附件与历史版本组织，事实可追溯至原文。设置按模型、搜索、通知、来源健康、备份和可选连接分组。能力检测和连接失败显示受影响功能，迁移报告提供可检查的结果。

## 4. 组件及交互约束

- 岗位记录、目标条件、资格行、证据引用、运行摘要、接管面板、版本选择和时间线在各入口保持语义一致。
- 保存操作显示实际生效对象与条件。重试使用同一业务操作 ID，版本冲突保留用户草稿并显示最新值。
- 加载期间保留已显示结果和阅读位置。分页错误在末尾重试，流式断线提供恢复状态。
- 状态以文字、图形和颜色共同表达，未知项有具体原因，部分成功显示可使用的结果。
- 外部通知区分待发送、渠道已接受、失败和结果未知，站内已读独立展示。
- 公司、岗位、日期、数量和匹配结论来自实际数据，示例内容在开发和评审中明确标识。

## 5. 响应式与可访问性

桌面约 176px 导航，主体弹性填充，上下文栏 280–320px。平板折叠上下文栏。手机使用抽屉导航、纵向记录、可换行条件和完整操作面板。长来源 URL 显示可理解的链接名称，全文按需展开。

交互控件主要触达高度至少 44px，正文对比度目标 4.5∶1。键盘可完成导航、筛选、编辑、审批和恢复。弹层管理焦点并在关闭后返回触发点。语义标题、表单标签、错误关联和运行状态播报齐全。放大及软键盘出现时保证输入和确认动作可达。

## 6. 实现与验证顺序

先实现全局导航、目标上下文与基础状态，再完成助手到机会的发现流程、目标订阅、材料填写及申请今日闭环。逐页对照交互设计的需求映射，使用真实业务接口及可控测试来源。

在 1440px、1024px 和 390px 检查长内容、空数据、全部失败、部分成功、运行中、等待接管、结果未知和恢复。完成键盘流程与前端构建，再通过 A/B/C 场景检查任务连续性。当前文档中的线框、token 和默认策略需结合实装与用户观察调整。
